# Commy

Commy is free, open source voice and text chat for communities, written in Rust. It comes with private P2P voice, P2P file sharing (isolated to your server), soundboards, emojis, images, and screen sharing with no paywall. Messages and server state sync through an end-to-end encrypted sync service, not peer to peer.

## Project Structure

Commy ships as a desktop app for Windows, macOS and Linux, phone apps for iPhone and Android (`apps/desktop/mobile/`), and a browser client (`apps/web`). Calls, screen sharing and file sharing use iroh. `auth/` is the account server: Better Auth on Postgres with email, passkeys and social sign-in. The hosted services in `deploy/` run as Docker Compose stacks that Dockhand shows.

## Key Files & Directories

- `Cargo.toml` - workspace root; pins shared dependency versions (iroh 1.4)
- `crates/commy-core/` - domain model: ids, users, servers, channels, messages, permissions, `ServerState` (replicated, idempotent event application)
- `crates/commy-net/` - P2P: `ServerTicket` invites, versioned gossip `Envelope` protocol, `CommyNode` iroh wrapper (gossip topics per server, blobs for files)
- `crates/commy-sync/` - end-to-end encrypted sync streams (keys, sealing, wire format, native client); `crates/commy-sync-server/` is the service that stores and fans them out without reading them
- `crates/commy-audio/` - voice DSP: `VoiceProcessor` with RNNoise noise cancellation toggle, mute gate, VAD (480-sample frames at 48 kHz)
- `crates/commy-media/` - device I/O: cpal mic capture and playback, `JitterBuffer`, `Mixer`, xcap screen capture to MJPEG
- `apps/desktop/src-tauri/` - Tauri 2 shell: commands in `src/lib.rs`, state in `src/state.rs`, voice/screen orchestration in `src/media_engine.rs`, disk persistence in `src/persist.rs`; the view models it renders live in `crates/commy-view/`
- `apps/desktop/ui/` - static frontend (no build step); works in a browser with a mock backend for preview; `images/`, `sounds/` (soundboard clips in `sounds/soundboard/`), `scripts/` (`emoji.js` holds the picker data, regenerated by `node apps/desktop/tools/emoji-data.mjs <unpacked emojibase-data>`), `styles/`, `fonts/`
- `apps/streamdeck/` - Stream Deck plugin (TypeScript, Elgato SDK) that plays soundboard sounds through the app's loopback-only control channel in `apps/desktop/src-tauri/src/stream_deck.rs`; "Stream Deck plugin" CI builds it and releases attach `commy-soundboard.streamDeckPlugin`
- Single copy: one running copy per data dir (`running.lock`, `src/single_instance.rs`); a second launch hands its link or a show request to the running copy over the `link.port` handoff and exits, and `relaunch::restart` must stay the only restart path so the old copy stops answering first
- Data folder: `data-folder.txt` in the standard folder points at a folder chosen in the Windows installer page (`src-tauri/installer/`, patched into Tauri's NSIS template by the release config) or in Settings > Storage; moving and clearing everything run on the next start before any window (`src/data_location.rs`), and a move copies, checks every byte, carries the local key, switches, then removes the old copy
- Dev testing: run a second instance with `COMMY_DATA_DIR` set for P2P testing on one machine (its webview storage moves there too, `COMMY_INSTANCE_LABEL` names the window); `auth/docker-compose.dev.yml` runs a local account server with mail catcher, Redis and Prisma Studio, optional keys go in `auth/.env`; `COMMY_AFK_SECS` shortens the AFK timeout; UI edits need `cargo build` (assets embed at compile time)
- CI: "Rust checks" (`.github/workflows/rust.yml`) compiles every PR that touches Rust on Linux, and on Windows and macOS unless the PR only changes crates with no OS-specific code (`apps/web`, `commy-view`, `commy-bot`); phone-only files and docs skip it; never run "Desktop release" by hand to prove a branch compiles
- The commy.chat website (Next.js) lives in its own private repository, commy-web; `auth/` is the Better Auth account server and `deploy/` the hosting stack

## Development Guidelines

### Coding Style

Avoid emojis and M-Dashes. Use generated assets and icon libraries.

No code comments, in any language or file type (Rust, JavaScript, CSS, HTML, shell, YAML, TOML, Dockerfiles, Caddyfiles). Rust doc comments (`///`, `//!`) count as comments. Make the code say it instead: clear names, named constants, small functions, and tests for the behaviour that matters. The only exceptions are license or SPDX headers, `// SAFETY:` notes on unsafe blocks, and tool directives (`#[allow]`, `eslint-disable`, `@ts-` directives, `# shellcheck disable`, shebangs). `deploy/.env.example` keeps its notes because it is the operator's setup guide, not code.

### Testing Approach

Create Robust Unit Tests for all new modules written, QA testing is high priority. 

Never name other chat products or their paid tiers in code, comments, docs or UI copy; describe Commy on its own terms.
Never put personal names or emails in the repo; the public identity is Commy Commander.

## Files to Avoid

- node_modules/
- .env files
- Build artifacts (dist/, build/)
- Log files

## Special Instructions

We are aiming for a complete, familiar community chat app on desktop, phone and web (servers, channels, roles, voice, screen share), seamless to install and set up. Voice, screen sharing and files go peer to peer; the hosted side is the website, accounts, sync servers and relays in `deploy/`.


## Playbooks

Keep this file short: it is read before every task. Long procedures belong in
their own file, referenced here, and loaded only when the task matches:

- Cutting a release → the "Cut release" workflow (`.github/workflows/cut-release.yml`); deploys and promotions → `deploy/DEPLOYING.md`
- Changing who is in which voice channel (seats, devices, presence expiry) → read `docs/voice-seats.md` first

## Git

- Conventional commits; branch from the latest `main` as `<type>/<short-name>` with the commit type (`feat/`, `fix/`, `docs/`, `ci/`); see `CONTRIBUTING.md`.
- Do not run `cargo fmt`: there is no `rustfmt.toml`, the code is not rustfmt-formatted and CI does not check formatting, so it rewrites many unrelated files.
